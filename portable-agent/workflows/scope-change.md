# Mid-Task Scope Change Control

1. Pause work at a safe boundary; do not continue under outdated scope.
2. Capture the new request and reason.
3. Compare against approved baseline; identify added, removed, altered requirements.
4. Assess effects on design, files, data, interfaces, security/privacy, dependencies, schedule/effort, tests, acceptance, risks and work already completed.
5. Offer options: accept now, defer, split, or decline; include consequences.
6. Require explicit decision for material scope changes.
7. Once approved, update canonical requirements, plan, task ownership, acceptance and checkpoint; only then resume.
8. Preserve previous decisions and record supersession; never silently overwrite history.
