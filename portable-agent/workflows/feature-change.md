# Feature / Change Workflow

1. Recover existing project instructions, baseline requirements, current implementation and task state.
2. Describe feature goal, users, trigger, expected behavior, exclusions and constraints.
3. Trace impacted UI/API/process/data/security/dependencies; inspect actual implementation before assuming.
4. Compare change against baseline; distinguish new requirement, clarification, bug, and refactor.
5. Define acceptance criteria, edge cases, compatibility, test strategy, and risks.
6. Identify decisions or migrations requiring approval. Prepare a bounded implementation plan.
7. Do not implement while materially ambiguous or approval-sensitive.
8. After approval, implement incrementally using `workflows/implementation.md`; verify and review.
9. Update canonical requirement/decision/task records and handover.

Deliver: change summary, impact map, baseline delta, open questions, approval, plan, tests and evidence.
