# Requirements Analysis
Use for requirements elicitation, ambiguity resolution, and acceptance definition.
1. Identify business goal, actor, trigger, current process, desired outcome, constraints and scope.
2. Separate explicit requirements, inferred assumptions, unresolved questions and out-of-scope items.
3. Capture functional requirements with IDs and measurable acceptance criteria.
4. Capture edge cases, failure paths, permissions, validation, data lifecycle, audit and NFRs.
5. Check contradictions and dependencies; prioritize by impact.
6. Confirm only material ambiguities; do not re-ask answered questions.
Deliver: concise requirements, assumptions/questions, exclusions, acceptance criteria and traceability.
